# 界面缩放与处理控制设计

## 状态

用户已批准，并授权后续自主实施、验证、更新说明、提交和推送。

## 方案比较

| 方案 | 效果 | 实现与维护成本 | 风险与验证 |
| --- | --- | --- | --- |
| 完成当前文件后安全停止，复用现有处理流程 | 点击停止后显示正在停止；当前文件完成保存，不再开始下一份 | 最低，不改配对算法；以后可逆地增加更细停止粒度 | 大文件等待较久；验证当前文件完整、后续未处理及状态恢复 |
| 中途取消当前文件，保存阶段禁止打断 | 计算阶段更快停止，当前文件不输出不完整结果 | 较高，需要向分组计算、并行任务及阶段边界传递取消状态 | 验证多进程收尾、取消与保存竞态、旧文件保护；可逆但改动范围更大 |
| 独立子进程运行并强制终止 | 有机会迅速结束计算 | 最高，需要额外协调弹窗、日志、进度及结果发布 | 强制终止可能遗留中间文件，不符合本次最简安全要求，不推荐 |

推荐第一种。停止是请求结束本次运行，不能承诺立即结束当前大文件。

## 界面结构

- 输入区：选择文件、选择文件夹、包含子文件夹，显示当前选择。
- 设置区：异常金额阈值、两项可选筛选。
- 执行区：常驻开始处理和停止处理，紧邻状态与进度。
- 日志区：随窗口扩展，保留足够阅读空间。
- 单文件列映射与批处理列映射采用一致的清晰字体和列表尺寸，优先复用现有映射窗口，减少两套重复布局。
- 映射确认仅完成配置，不代替主界面的开始按钮；批处理在运行中遇到新格式仍按现有规则询问一次。
- 增大映射字体和下拉列表字体；窗口尺寸按可见空间安排，不仅放大窗口而保持文字不变。
- 映射必须完整显示五个必需字段及可选凭证种类，不只显示缺列。同名字段自动填好，非同名字段由用户核对选择，不以模糊关键词自动认定字段含义。

## 数据流

1. 选择资料只记录输入与显示准备状态，不启动计算。
2. 点击开始时读取当次阈值、递归开关和筛选开关，检查输入及参数。
3. 单文件完成必要映射及筛选配置后运行现有处理流水线。
4. 批处理继续复用现有扫描、映射缓存、筛选缓存、独立结果目录与清单。
5. 主界面用标准库线程事件记录停止请求。单文件完成后提示已经停止且当前结果已保存；批处理在文件边界检查请求，更新剩余未处理原因并保存清单。
6. 完成、失败或停止均恢复按钮；停止请求每次启动时清空。

## 错误处理

- 输入或阈值非法时不启动运行，清晰提示原因。
- 点击停止后不能重复开始，等待当前文件收尾。
- 当前文件失败时仍按原有失败规则记录，停止原因不能覆盖真实失败原因。
- 映射或筛选弹窗取消沿用现有语义，不混淆取消一种格式与停止整个批次。
- 运行中关闭窗口继续受保护，不能用关闭窗口强制中断保存。

## 测试策略

- 先写实际行为测试证明选择不会自动处理、开始按钮会触发处理。
- 检查空闲、运行、停止请求、结束后的按钮状态以及再次运行。
- 批处理停止后检查当前结果可打开、后续没有输出、清单为未处理并注明原因。
- 检查单文件停止提示与当前完整输出。
- 以现有桌面测试方式覆盖映射确认、取消及主窗口恢复。
- 检查普通 Tk 与 CustomTkinter 字体、列表、不同缩放下的布局尺寸。
- 运行全量测试及现有回归检查，对照 README 的实际操作顺序。

## 迁移与回滚

- 修改前备份所有受影响已有文件到项目外 Backup 子目录。
- 保持主入口及独立命令行接口不变；未传入停止事件的批处理调用行为不变。
- 不新增依赖、不自动提交中间阶段。最终验证后按用户授权创建新提交并推送，不强推。
- 不重建或覆盖旧 EXE，README 明确本次源码更新范围。
- 本设计容易调整，不满足单独架构决策文档的门槛；通用开始、停止概念不新增到业务术语表。
