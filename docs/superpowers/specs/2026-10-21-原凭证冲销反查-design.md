# 原凭证冲销反查设计

## 方案比较

1. **推荐：处理前查证，按凭证传递核对结果。** 先在同一账套内查原凭证并逐行唯一配对，处理目标凭证时优先拆出已查实的冲销行。保留现有分录算法和并行方式；改动集中，未查实的行不受影响。
2. 在每张凭证的拆分算法里直接搜索全账。会重复扫描、拖慢处理，也使拆分算法依赖全账数据。
3. 只给原有候选分法加一个分数。能提供提示，但无法保证已查实的冲销业务一定不与新业务混配。

## 数据流与边界

输入仍是一份序时账。先照旧处理全部凭证，再按账套、确切凭证日期、凭证字和号码索引旧凭证；对写明原凭证的每一条冲销行，核对详细科目、去掉引用前缀后的原摘要、金额相等且借贷方向相反。候选有重复或缺字段即不认定。所有冲销行与原行一一对应、双方金额平衡、目标凭证整体平衡时，形成一个独立的冲销组。

原凭证结果来自同一次现有匹配。若相应原始行的输出分拆后逐行合计等于原金额，且均有明确对方科目，复制对方科目和对应拆分金额到冲销行，保留冲销行原有借贷列与符号；否则冲销组独立运行现有流程。剩余的新业务继续原流程。含结转损益科目的凭证维持整张凭证优先处理；同一凭证内只要有一条标明冲销的记录查不实，整张凭证按现状处理。无跨文件关联、无猜测摘要、无新依赖。

## 验证和回退

先写端到端失败测试，覆盖独立拆分、金额守恒、重复候选、缺字段及不同账套，再实现。用修竹真实凭证的小片段作只读复核，不全量重跑业务账。可用 Git 提交回退；本次不改原始工作簿。
