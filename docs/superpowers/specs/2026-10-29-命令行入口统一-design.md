# 命令行入口统一设计

## 目标

以主程序现有 `--no-gui` 为唯一无头模式，增加一种普通简版输出。旧 CLI 源码只转调主程序，不再维护独立逻辑，也不重新打包 exe。

## 方案比较

| 方案 | 做法 | 判断 |
|---|---|---|
| 主程序无头模式加 summary（采用） | 共享流水线默认完整输出，显式 summary 时写普通“生成结果”；旧 CLI 只调用 `main.main()` | 符合用户纠正，改动最少，彻底消除独立 CLI 逻辑 |
| 保留独立 CLI 的 summary/full 普通输出 | 在共享流水线中保留三种输出并重新打包 exe | 仍有两种 CLI 呈现和兼容包袱，且用户已明确否定重新打包 |
| 只改文档、不改主程序 | 告诉 Agent 使用现有 `--no-gui` | 没有简版输出，不满足需求 |

## 结构与数据流

```text
桌面 GUI ───────────────┐
主程序 --no-gui ────────┼─> 共享 run_processing_pipeline
旧 CLI 转调 main.main() ─┘             │
                                      ├─> full：主程序完整美化输出（默认）
                                      └─> summary：普通“生成结果”表
```

`run_processing_pipeline(..., output_mode="full")` 负责筛选、处理和校验：

- `full`：保持现有异常检测、班福分析和 `save_output_file` 行为。
- `summary`：处理与校验后直接写普通“生成结果”表，不计算异常和班福分析；启用筛选时仍追加筛选结果表。

GUI、文件夹批处理和主程序默认无头模式不传新参数，继续走 `full`。

## 模块调整

- `src/pipeline/orchestrator.py`：接收 `output_mode`，默认 `full`，仅增加 `summary` 分支；未知值明确报错。
- `src/io/writer.py`：抽出生成结果列排序供完整和简版共用；增加普通 summary 写出及表头居中。主程序完整写入保持不变。
- `main.py`：增加 `--mode full|summary`，默认 `full`，并传给共享流水线。
- `cli/序时账分析器命令行版.py`：只保留项目路径引导和 `main.main()` 转调。
- `src/__init__.py`：提供唯一 `__version__`；主程序和 GUI 读取它，旧 CLI 因转调自然使用同一版本。
- `README.md`、`cli/ledger-cli-README.md`：以主程序无头模式为准，说明旧 exe 不再维护且本次不重新打包。
- `cli/ledger-cli.exe`：**保持原文件不动。**

## 错误处理与兼容性

- 主程序输入读取、处理或保存失败仍返回退出码 `1`，成功为 `0`；argparse 用法错误沿用其标准错误码。
- 主程序原有缺列处理不变，不恢复旧 CLI 的 `-i` 交互选单。
- 保存函数返回布尔结果，主程序进度回调和错误日志不变。
- 旧 CLI 的默认行为随主程序统一为 full；这是用户选择“只保留无头入口”后接受的行为变化，不再保留另一套默认 summary。

## 测试策略

1. 用真实子进程检查主程序和旧 CLI 帮助均显示当前版本；旧 CLI 的 v2.2.1 会使测试先失败。
2. 用真实主程序无头命令验证 `--mode summary` 只生成普通“生成结果”；旧 argparse 不接受该参数，测试先失败。
3. 用旧 CLI `--mode full` 验证其输出包含主程序的班福图表；旧独立 full 无图表，测试先失败。
4. 验证未知内部输出模式明确报错，筛选下 summary 追加筛选表，主程序默认完整输出和既有算法测试不变。
5. 运行定向测试和完整 pytest；只验证源码入口，不构建或修改 exe。

## 迁移与回滚

Agent 改用主程序无头命令；旧 exe 保留为历史文件但不再作为文档推荐入口。若改造出现问题，按备份恢复源文件或回滚本次提交，无需数据转换，也不涉及 exe 回滚。

本设计不新增依赖，不处理同表多图、旧文件覆盖或 pandas 弃用警告。无需 ADR：方案可逆，设计文档已记录用户纠正和取舍。
