# 文件夹批处理需求

## 背景与问题

当前桌面界面只能选择一个序时账文件，选择后自动执行读取、列名配置、分析和导出。用户需要通过浏览选择一个文件夹，连续处理其中的序时账，减少重复选择文件的操作。

## 用户与使用场景

使用者为处理序时账的财务或审计人员。用户确认本次批量输入的格式和筛选口径一致，不需要每份文件重新确认时间或审批筛选条件。

## 已确认的功能范围

1. 保留单文件入口，增加浏览选择文件夹的批处理入口。
2. 增加“包含子文件夹”开关，默认不勾选。不勾选时仅处理选定目录根层的文件；勾选时包含所有子文件夹。
3. 每次批处理新建带时间的“批处理结果”文件夹；每份输入独立输出，保留输入相对于选定目录的子文件夹层次，防止同名文件覆盖。
4. 跳过 Excel 临时文件和已生成的“生成对方科目”文件；扫描时避开本工具的批处理结果目录，避免重复分析历史结果。
5. 单份文件损坏、不是可处理的序时账或存在非法金额时，记录失败原因，继续处理其他文件。最后生成逐文件的处理清单，列出成功、失败和对应原因。
6. 遇到需要人工对应的新列名格式时只询问一次，相同格式在本批次内复用已确认的对应关系；不跨批次保存。
7. 原有时间筛选和拆分审批筛选仍默认关闭。启用后只在第一份可处理的账上设置一次，本批次后续文件使用相同设置，不逐份询问。
8. 批处理复用原有对方科目生成、异常分析、班福分析、数据验证和输出格式，不把多份文件合并成一份账。
9. 完成后同步更新 README，并执行用户已授权的提交和推送操作。

## 明确不做

- 不修改凭证内分录识别和现有配对算法。
- 不合并不同输入文件的凭证或金额。
- 不自动判断用户选择的日期字段或审批限额是否符合实际业务。
- 不增加跨批次设置持久化。
- 本次以桌面文件夹浏览为入口，不默认扩展独立命令行的批处理参数。

## 约束与风险

- 修改已有文件前，必须备份到项目外的统一 Backup 目录，按项目名和时间建立子目录。
- 原始输入文件不修改，批处理不能覆盖历史结果。
- 选择文件夹不等于其中所有 Excel 都是序时账；无法处理的文件必须明确列入失败清单，不能静默消失。
- 列名格式相同只表示可以复用字段对应关系，不代表自动证明数据含义一致；筛选口径一致是用户明确确认的输入前提。
- 读取程序当前只读取每个工作簿的第一张工作表，本次保持该行为，README 必须写明。
- 桌面运行中不能重复启动另一批处理，以免当前文件、进度或设置互相干扰。
- 已发布的可执行程序不会自动包含源码变更；是否重建桌面程序在方案阶段根据现有打包条件说明，不把源码验证当成可执行程序验证。

## 验收标准

1. 未勾选子文件夹开关时，子目录文件不处理；勾选后处理子目录文件。
2. 每份账独立生成结果，子目录同名输入不会互相覆盖，原始文件内容保持不变。
3. 临时文件、已生成结果和历史批处理目录不参与分析。
4. 混合正常文件与坏文件的批次可以继续完成；处理清单包含每个候选文件的状态和失败原因。
5. 相同格式缺列文件只配置一次，不同格式需要重新确认；本次取消配置的处理方式在设计中明确。
6. 筛选关闭不弹筛选设置；筛选启用时整批只设置一次，后续文件导出对应筛选表。
7. 显示当前处理文件、批次进度以及最终成功和失败数量；运行中避免重复启动。
8. 空目录或没有候选文件时明确提示，不误报成功。
9. 原单文件流程和已有测试保持通过；新增测试覆盖真实文件扫描、处理、失败继续、设置复用和桌面入口。
10. README 描述与实际功能、已验证范围一致；提交仅包含本次相关变更，推送完成后核对仓库状态。
