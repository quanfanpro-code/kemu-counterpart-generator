# 原凭证冲销反查需求

## 背景与使用场景

同一张凭证可能同时记载冲回旧业务和重新入账的新业务。现有程序能在凭证内拆分分录，但没有根据冲销摘要中的日期和凭证字号回查旧凭证，容易把两笔业务混配。修竹账中，2026-07-01 记-2号凭证冲回 2026-02-01 记-17号凭证的旧处置业务，同时重新入账，属于可复核样例。

## 范围与约束

- 从同一份序时账中查找摘要明确引用的原凭证，分别核对账套、凭证日期、凭证字、凭证号、明细科目、原摘要及等额反向金额。
- 仅当每条冲销行唯一对应一条原始行、原始行未被重复认领，且冲销行自身借贷平衡时，才把它们从同张凭证的新业务中分开。
- 原始行已有完整、金额可追溯的对方科目结果时，把对应关系和拆分金额反向用于冲销行；否则仅隔开已核实的冲销行，再用原有匹配流程处理。
- 保留原始借贷列、金额、行号和账套；无引用、引用错误、重复候选、缺少明细科目或日期时，保持现有处理方式。
- 同一凭证若还有一条标明冲销的记录查不实，整张凭证保留原处理结果，不只改其中一部分。
- 结转损益原有最高优先级不变；标准模板、精确金额优先、其他算法和兜底实现不作改动。
- 不增加外部资料、界面设置和新依赖；不按修竹的科目、金额或凭证号写特殊规则；不改现金流量表技能。

## 验收标准

1. 引用完整且各行唯一对上的冲销凭证，冲销行沿用原分录对方科目；同张凭证的新业务独立处理。
2. 原凭证重号、同科目同摘要同金额重复行、摘要不同、科目不同、金额不反向、日期不足、账套不同，均不得强行沿用。
3. 输出逐原始行保留借贷发生额；串行与多进程结果一致；原有测试通过。
4. README 说明触发条件、处理方法和不能唯一核对时的做法；提交并推送源代码。
