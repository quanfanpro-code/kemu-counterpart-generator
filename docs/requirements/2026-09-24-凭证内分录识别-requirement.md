# 凭证内多笔分录识别：需求与流程风险核查

## 背景与目标

原始序时账只标识凭证，不标识一张凭证内哪些原始行属于同一笔会计分录。当前程序按账套（如有）、会计月、凭证种类（如有）、凭证编号划分凭证，再将整张凭证交给现有配对流程。因此一张凭证含多笔分录时，标准模板、金额配对或兜底拆分可能跨分录关联科目。

目标是在现有配对流程前增加一层分录识别：依据有借有贷、借贷金额相等，并允许原始行顺序辅助推断；只在可以作出可信划分时，将完整原始行分组后分别交给原有算法。现有配对算法及其优先次序保持不变。

## 用户与使用场景

使用者为处理序时账的审计或财务人员。典型场景是一张凭证含两组或更多借贷平衡记录，例如第一组一借多贷，第二组一借一贷；整张凭证内存在相同金额时，当前算法可能把第二组借方与第一组贷方配对。

已在当前代码做只读复现：凭证按顺序记录“借甲100、贷乙60、贷丙40、借丁60、贷戊60”时，现有算法把“丁”配给“乙”，再把“甲”配给“戊”和“丙”；这与连续两组分别平衡的分录划分不同。另一个复现为“借本年利润100、贷主营业务收入100、借管理费用50、贷银行存款50”，当前结转规则把管理费用与银行存款也指向本年利润。

## 已确认范围

- 用户允许使用原始行顺序作为借贷平衡之外的辅助依据；行顺序本身不构成真实分录的证明。
- 新流程只改变凭证送入现有匹配算法前的分组，不改结转损益、标准模板、金额匹配、兜底拆分和它们的优先次序。
- 分组以完整原始行为单位；新流程不拆金额、不改金额、不改科目、不跨凭证或账套。
- 无法可靠区分多笔分录、数据异常、运算超出安全界限时，整张凭证按现有流程处理。正常的不拆组无需逐张新增提示；新识别步骤发生异常时记录原因。未经判定为多笔的凭证，结果应与修改前一致。
- 桌面版、主命令行入口和独立命令行版都走共同的凭证处理入口；源代码变更后，已打包的 EXE 需重新构建、验证，才会包含新功能。

## 不能从原始数据推出的结论

借贷平衡只是可能分组的必要条件，不足以证明原始制单者的真实分录边界。同一凭证“借甲100、借乙100、贷丙100、贷丁100”既可有不止一种一借一贷配法，也可能是一笔多借多贷分录。不能把任意一种平衡分法标成已证实事实；出现同等合理划分时应保留原流程。

## 按现有流程核查的风险与约束

| 环节 | 现状和风险 | 需求约束或验收点 |
| --- | --- | --- |
| 读取和预处理 | 会计月、凭证号等空值向下填充；表尾汇总行剔除；空科目仍可能保留；原始行次可用。若新流程先行排序，会破坏行序证据。 | 只在预处理及凭证分组后识别；保留原索引和相对行序；不得改变读取、列映射、汇总行及金额规范化行为。 |
| 凭证分组和并行 | 现有分组键可含账套；小批量串行、大批量按凭证并行；最终按原始行索引恢复顺序。 | 分录识别只在单张凭证内部发生；串行和并行结果一致；不泄露内部组标识到原始数据或结果列。 |
| 结转损益特殊规则 | 当前只要一张凭证恰有一个“本年利润/利润分配”条目，就优先把其他条目纳入特殊规则并提前返回；多条这类条目时改走通用匹配。先拆组会改变特殊规则的触发范围和输出。 | 必须单列纯结转、混合结转与普通业务、多条利润科目、结转调整等回归样例。特殊凭证的分组政策待确认，不能让新流程无意绕过或扩大该规则。 |
| 标准模板 | 当前在整张凭证内先一对一、再一对多和多对一，科目规则可跨真实分录命中。 | 规则表和优先次序不改；识别出的不同分录组不得跨组匹配；未分组的凭证结果与旧版逐行一致。 |
| 金额配对与兜底拆分 | 当前按金额排序后逐步配对；首个同金额或凑数解可能跨真实分录，剩余金额仍会被兜底配对。 | 只缩小明确分组凭证的候选范围；组内完全复用原算法；无可靠分组时继续原路径。 |
| 金额精度与异常行 | 现有精度引擎按整数厘比较，默认相等容差一分钱；红字会改变其参与配对的借贷方向；同行借贷双非零会拆成两个条目并警告；零金额或空科目会跳过。 | 分组判定必须与现有金额、借贷方向语义一致；红字、借贷同行双非零、空科目、零金额和不平衡凭证不能被新流程静默误分。 |
| 结果校验 | 目前主要核查整表借贷合计和对方科目格式，金额相同而配错科目仍可通过。 | 增加按原始行与凭证检查金额守恒、不重不漏及组内平衡的行为测试；不能只凭整表合计判断成功。 |
| 异常分录分析 | 使用配对后的结果，且跳过标准模板和结转损益匹配；配对改变会改变异常明细及汇总。 | 在明确分组样例核对后续异常输出；未分组样例保持旧输出。不得把业务筛选变化误称为独立分析模块的修改。 |
| 班福分析和可选筛选 | 班福和时间、审批筛选读取原始数据，不依赖新配对分组。 | 新流程不得修改原始数据对象；启用和关闭筛选时均验证结果不变。 |
| 保存及入口 | 桌面版和主命令行使用同一流水线，独立命令行共用 perform_processing；完整与精简版输出格式不同，旧 EXE 不会自动更新。 | 验证三个源代码入口及相应输出模式；不新增无需求的结果列；发版时另做 EXE 构建及入口验收。 |
| 性能与故障 | 组合枚举在行数多或同金额重复时可能迅速膨胀；新流程异常会使整个凭证失败。 | 分组计算设置有限界；超界或判定异常则退回原处理，并留下可追踪提示。 |

## 明确不做

- 不修改既有匹配阶段的具体规则、排序、金额拆分及容差。
- 不声称可以仅凭平衡金额还原真实制单意图；不自动采用多种等价分法中的任意一种。
- 不改原始数据、凭证分组键、班福及可选筛选业务规则；需求调研阶段不提交、推送或发布，整体交付按用户后续授权执行。

## 验收标准草案

1. 原本只含一笔分录、未能可信分组、异常数据、红字及特殊处理需保留原路径的凭证，与旧版逐行比较：原行顺序、科目、发生额、对方科目、匹配类型及警告相同。
2. 明确可划分的普通多分录凭证按组调用原匹配流程，不跨组关联；覆盖一借一贷、一借多贷、多借一贷和重复金额。
3. 混合结转凭证仅在可靠识别独立平衡组后拆组，原结转规则只处理所属组；多条利润科目凭证保留整凭证旧流程；纯结转行为不得回退。
4. 对每张凭证校验原始行不重不漏；输出金额与旧算法的既有守恒约定一致；串行与并行一致。
5. 桌面版、主命令行、独立命令行及精简/完整输出、下游异常分析和可选筛选均通过针对性验证；构建发布时验证对应 EXE。
6. 对大凭证和无法唯一判断的凭证给出有界处理与回退证据，不能因新步骤造成卡死或整凭证丢失。

用户已确认：同一凭证同时含损益结转及其他独立平衡分录时，允许在可靠识别后拆组，让现有结转规则只处理所属组；含多条“本年利润/利润分配”条目的凭证先保留整凭证旧流程，避免绕过现有防误合并措施。
