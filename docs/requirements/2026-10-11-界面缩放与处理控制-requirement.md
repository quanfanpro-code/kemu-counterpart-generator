# 界面缩放与处理控制需求

## 背景与问题

用户在 2K 屏幕上反馈列映射文字太小，且主界面没有独立的开始处理、停止处理按钮。

已核查主界面使用显式的 9 至 10 小字号显示单文件映射；批处理映射使用普通 Tk 默认字体，两种映射界面设置不一致。单文件选择完成后直接处理，文件夹选择完成后直接启动批次；停止按钮及停止请求均不存在。

实际窗口探测记录显示 CustomTkinter 控件缩放为自动机制，普通 Tk 默认字体为微软雅黑界面字体、字号 9。尚未完成用户实际 2K 屏幕上的视觉验收，不把字号偏小等同于已证明自动缩放失效。

## 用户与使用场景

Windows 桌面用户处理单份序时账或整个文件夹，需要清晰阅读列名并控制处理开始和停止。

## 已确认范围

- 放大并统一列映射字体、下拉框与行间距，适配 Windows 显示缩放。
- 选择文件或文件夹只准备输入，不自动启动计算。
- 常驻显示开始处理与停止处理按钮；未选择输入时不能开始，未运行时不能停止。
- 开始前允许调整异常金额阈值及可选筛选。
- 使用安全停止，保留批处理中已完成结果，剩余文件明确列为未处理，正在保存的文件完成保存后再停。
- 运行期间防止重复启动；结束或停止后恢复操作。
- 同步更新 README 中的操作说明及更新日志。
- 用户于本轮明确授权验证完成后创建提交并推送。

## 明确不做

- 不修改凭证配对、红字分录边界、筛选口径或结果格式。
- 不引入额外依赖，不自动安装工具。
- 不强杀工作进程，不删除未处理资料，不覆盖其他用户改动。
- 本轮未要求重新打包桌面或独立命令行 EXE；源码更新不代表旧 EXE 自动更新。

## 约束与风险

- 所有已有文件修改前备份到项目外的统一 Backup 目录。
- 单文件和批处理需要分别验证选择、开始、停止与恢复状态。
- 映射弹窗继续保持正常的窗口焦点和关闭后主窗口恢复行为。
- 停止粒度会影响等待时间，具体方案需在设计阶段批准。
- 缩放需同时检查文字、下拉列表、窗口可见空间和执行按钮是否可见。

## 验收标准

1. 选择资料后没有开始计算或生成结果，点击开始后才运行。
2. 单文件及批处理均有可见的开始、停止按钮，按钮可用状态与任务状态一致。
3. 停止后不再启动后续文件；已经正式保存的结果仍可打开，清单说明停止原因。
4. 停止不会将不完整结果标为成功，结束后能再次开始。
5. 映射文字和列表字体统一放大，无文字、按钮被遮挡；不同缩放设置有自动检查。
6. 已有相关测试与新增行为测试通过，README 与最终实际行为一致。
7. 提交、推送后核实远端对应提交。

## 已批准决策

- 用户批准完成当前文件并保存后停止，后续阶段自主完成，无需再次确认。
- 用户现场指出只显示凭证种类不足以核对映射；需要映射时完整显示五个必需字段，另列可选凭证种类，同名字段自动填好。
