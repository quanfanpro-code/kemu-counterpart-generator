# 全程序独立复核：需求

## 背景与问题

本工具（序时账对方科目自动生成，当前 v2.2.0）历史上做过两轮全面复核（v2.0.7、v2.0.8），此后新增了入账时间/拆分审批筛选（2026-09-08）和凭证内多笔分录识别（2026-09-24，当前 HEAD 4b4c740）。新增功能改变了送入匹配算法前的凭证划分，也新增了日历、筛选两个业务模块，整体需要一轮覆盖全部模块的独立复核。

用户（仓库所有者）明确要求：用需求优先工作流独立复核整个程序；复核中发现的确认问题直接修复并验证；完成后同步更新 README（修正与代码不符的描述 + 更新日志新增复核记录并升版本号）；提交并推送到 origin/main（本轮已明确授权 Git 写操作，直接推 main，不开分支不建 PR）。

## 用户与使用场景

使用者为审计/财务人员，通过桌面 GUI、主命令行或独立 CLI（ledger-cli.exe）处理序时账 Excel。复核的直接受益人是这些终端用户：复核要消灭的是"结果悄悄出错"类隐患（金额失真、配对错误、行列丢失），其次是 README 误导使用者的描述偏差。

## 功能范围（已确认）

1. 全模块逐文件复核，范围：
   - `main.py`、`make_excel.py`、`cli/序时账分析器命令行版.py`
   - `src/core/`（precision、algorithms、rules）
   - `src/pipeline/`（orchestrator、group_processor、anomaly、validator、凭证筛选）
   - `src/io/`（reader、writer）
   - `src/gui/`（app、widgets、progress、log_redirector、筛选设置）
   - `src/日历.py`、`src/utils/logger.py`
   - `tests/`（现有测试是否真正验证行为）
   - `README.md`、`CONTEXT.md` 与代码实际行为是否一致
2. 复核重点按风险排序：会导致金额/配对/行列错误的数据完整性问题 > 逻辑 bug > 异常处理与边界 > 测试空洞 > 过度工程与死代码。
3. 确认的 bug 按 TDD 直接修复：先写能复现问题的失败测试，再最小修复，再跑全量验证。
4. 疑似但无法证实的问题列入复核报告"待人工判断"，不擅自改行为。
5. README 更新：修正与代码不符的描述；更新日志新增本次复核/修复记录；版本号按修复内容升级。
