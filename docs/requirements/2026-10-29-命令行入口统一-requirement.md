# 命令行入口统一需求

## 背景与问题

主程序已经支持 `--no-gui`，独立 CLI 却又维护了一套参数、处理编排和输出代码。用户明确要求：CLI 只是主程序的无头入口，最多增加一种简版输出，不应再作为独立软件维护或打包。

## 用户与使用场景

- 桌面用户：继续通过主程序生成带格式和班福图表的完整结果。
- Agent 与自动化脚本：使用主程序的无头模式；需要简洁数据时选择简版输出。

## 功能范围

1. 主程序无头模式支持 `full` 和 `summary`：默认 `full`，保持现有完整美化输出；`summary` 只输出普通格式的“生成结果”表，不加美化或图表。
2. 筛选、处理、校验、异常检测、班福分析和保存由同一套主流程负责；summary 不额外计算不需要的异常和班福分析。
3. `cli/序时账分析器命令行版.py` 仅转调主程序，不再保留独立参数解析、处理编排、列映射或写出逻辑。
4. 主程序和 GUI 从同一处读取当前版本号，旧 CLI 不再显示独立版本。
5. 更新 README 和 CLI 说明，引导 Agent 使用主程序无头模式。
6. 增加真实入口回归测试，覆盖完整输出、简版输出、旧 CLI 转调和版本一致性。

## 明确不做的内容

- **不重新打包、不修改 `cli/ledger-cli.exe`。**
- 不保留独立 CLI 的普通 full 输出、独立列映射或其他专属功能。
- 不扩展同表多图支持；程序当前只需要一张班福图表。
- 不调整匹配算法、GUI 操作或其他无关问题。
- 不新增第三方依赖，不删除旧 CLI 文件。

## 约束与风险

- 以用户最新纠正为准，不再沿用此前“完整保留独立 CLI 行为”的方案。
- 主程序默认完整输出的行为不能改变；简版只由显式 `summary` 选择。
- 可选筛选在 summary 下仍按现有约定追加结果表。
- 修改前备份所有将被覆盖的既有文件并校验；不处理范围外的历史问题。

## 验收标准

1. `main.py 输入 输出 --no-gui` 的完整输出与原来一致。
2. `main.py 输入 输出 --no-gui --mode summary` 只生成普通“生成结果”表；启用筛选时追加对应筛选表。
3. 旧 CLI 源码调用同一主程序；其 `--mode full` 输出与主程序完整输出一致，帮助中的版本也与主程序一致。
4. 主程序和 GUI 版本号同源，旧 CLI 不再包含独立实现。
5. README 与实际行为一致，明确旧 exe 不再维护且本次不重新打包。
6. 新增测试先因旧实现不满足目标而失败，随后通过；完整测试套件和真实入口错误路径验证通过。
7. 最终变更提交并推送到 GitHub `main` 分支。

## 调研摘要与来源

- `main.py` 已提供无头模式并调用共享 `run_processing_pipeline`。
- 旧 CLI 另行组合处理步骤和写出结果，属于需要消除的重复。
- 2026-10-29 全量测试最终结果为 168 个通过；pandas 3.1.0 的既有弃用警告不属于本次范围。
- 用户后续明确纠正：主程序本身就是无头入口，不重新打包 CLI。
