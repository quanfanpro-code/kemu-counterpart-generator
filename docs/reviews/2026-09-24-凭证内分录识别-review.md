# 凭证内分录识别复核记录

## 范围与结论

以需求、设计、实施计划为基准，复核新步骤是否只改变进入既有匹配器前的凭证切分。源码对比确认 `GroupProcessor.process()`、结转损益、标准模板、金额匹配、兜底拆分、金额容差及结果字段均未改动。识别成功时，每个连续平衡组分别调用旧处理器；无法完整分组时，整张凭证仍由旧处理器处理。

## 逐流程核查

| 流程 | 验证结果与剩余边界 |
| --- | --- |
| 读取、凭证键、串行/并行 | 新步骤只接在单凭证共同入口，不改变读取与凭证键。201 张凭证的串行和双进程结果逐格一致。 |
| 损益结转 | 纯结转与旧处理器输出一致；混合结转在形成完整平衡组时，普通业务不再被利润组吸收；多条利润科目的整张凭证保持旧处理结果。 |
| 标准模板、金额匹配、兜底 | 这三个阶段的代码未修改。普通一借多贷、多借一贷、重复金额及一借一贷场景验证不同组不跨组配对；未拆组样例逐行比较旧处理结果。 |
| 异常数据 | 红字、同一行借贷均非零、零金额、空科目、极小金额及不平衡尾段整凭证回退。新步骤异常时先运行旧处理器，再附带可定位提示。 |
| 结果、分析和筛选 | 行序及借贷合计守恒、输出列范围通过行为测试。源码入口与 EXE 的精简/完整工作簿均回读验证；完整模式保留班福分析，启用时间筛选时日历筛选表正常生成。现有审批筛选测试继续通过。 |
| 桌面入口 | 原完整测试在修改前有一项因成功提示被进度消息覆盖而失败；已修复排队消息覆盖完成状态的时序问题，桌面到导出的端到端测试随完整套件通过。 |
| 打包交付 | `cli_build.spec` 明确包含随包节假日日历，排除不参与运行的可选大库；本机 PyInstaller 6.22.3 构建成功，交付 EXE 的精简和完整模式均由真实入口处理临时工作簿通过。 |

## 已知限制

原始序时账没有分录编号。连续段在中间恰好借贷平衡时，仍可能属于同一笔复杂分录；本规则以用户允许的原始行序为辅助证据，不能证明制单人的真实意图。交错排列的多笔分录和受保护的异常凭证会保留旧算法。未使用真实客户账簿做业务验收；自动化样本与程序入口验证只能证明列出的行为。
