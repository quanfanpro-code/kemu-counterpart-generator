# 界面缩放与处理控制验收记录

## 结论

本轮开始、停止及完整列映射已实现并通过自动验证。没有发现尚未解决的阻断问题；用户实际 2K 屏幕最终观感仍需实际使用判断，不以自动测试替代视觉确认。本轮未重建 EXE。

## 问题与修正

| 问题 | 原因 | 修正及证据 |
| --- | --- | --- |
| 无独立开始、停止按钮 | 选择资料后直接启动，没有停止请求 | 选择后等待开始；常驻按钮及状态保护，单文件与批处理实际导出测试通过 |
| 映射字体小且不统一 | 单文件小字号，批处理默认字体，普通 Tk 与增强界面放大机制不同 | 共用映射窗口，像素字号、列表字体及间距按显示缩放调整；窗口实际创建验证 |
| 修改过程中仅出现一个映射项 | 误将缺少字段传入单文件映射窗口 | 先运行两项测试复现失败，再修正为五个必需字段及可选凭证种类，两项均通过 |
| 安全停止保护 | 不能强制中断当前保存 | 文件之间检查线程事件，当前完整结果保留，未处理清单注明用户停止 |

- 修改前全量测试：62 项通过。

- 业务输出回归：修改前采集基线，最终运行 `python tests\regression_check.py --verify <临时基线目录> --runner source --expect-centered`，返回 `REGRESSION_OK outputs=3 allowed_differences=header_horizontal_only error_exit=1`。其中 `error_exit=1` 是预期非法输入场景退出码，回归检查命令本身成功。
- `git diff --check` 通过，只有 Windows 换行转换提示，无空白错误。
- 字体及弹出列表验证，100%、125%、150% 控件缩放下五个必需字段、可选凭证种类和底部按钮可见。
- 窗口切换、配置缓存、筛选实际导出、停止时当前文件完整、剩余未处理及当前文件失败不误报成功均通过。

## 审查

- 停止在文件边界执行，不改变配对算法和保存过程；未传停止事件的批处理行为不变。
- 完成和错误均恢复按钮，停止请求在下一次开始时清空，重复启动受保护。
- 非负且有限的阈值在开始时验证。
- 单文件映射已采用相同窗口，不再保留旧小字号映射布局及隐藏确认按钮的重复逻辑。
- 非同名字段需要用户核对选择；同名字段自动填好，不新增模糊猜测。
- README 的当前操作步骤、筛选时机及安全停止说明与实现一致，历史日志保留历史事实。

## 范围与限制

- 仅源码及文档更新，不重建桌面或独立命令行 EXE。
- 单文件停止仍完成当前整个文件，大文件不能即时结束。
- 再次开始是新一轮运行，不是自动续跑未处理清单。
- 自动测试使用合成数据和现有基线，不代表逐行审计真实客户资料。
- 映射字段固定为六项，测试覆盖这些实际字段，不扩展任意数量字段的通用滚动表单。
- 已有文件修改前均备份到项目外统一 Backup；本轮不删除任何文件。
