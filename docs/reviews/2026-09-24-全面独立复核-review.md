- **现象**：`main.py 输入.xlsx 输出.xlsx --no-gui` 处理缺少"凭证种类"列的文件时报错退出（退出码 1），而 README §4.2 声明凭证种类是可选列，独立 CLI 也能自动按"无/不适用"处理。同一文件两个入口行为不一致。
- **复现证据**：构造 2 行无凭证种类列的序时账，main.py 退出码 1（"缺少必要列且未启用交互模式"），独立 CLI 退出码 0。
- **修复**：main.py 新增 `_auto_column_mapping`，命令行模式注入列映射回调：同名列自动对应，凭证种类缺失自动按"无/不适用"，其他必需列缺失仍返回 None 报错退出。
- **TDD 证据**：新增 `tests/test_主入口缺凭证种类.py`（2 个测试）。RED：修复前 `1 failed, 1 passed`（缺列文件退出码 1）；GREEN：修复后 `2 passed`；VERIFY：全量 `41 passed`，回归比对 `REGRESSION_OK`。
- **影响面**：只放宽主程序命令行模式的缺列处理；GUI 流程、独立 CLI、输出内容均不变（回归基线逐格比对证实）。

## 六、残余风险与待人工判断项

1. 桌面版"序时账分析器.exe"不在仓库内，含 main.py，需用户重新打包后才包含本次修复；cli/ledger-cli.exe 不含 main.py，不受影响（本次按用户决定不重建 EXE，README 已注明）。

3. 表尾汇总行剔除只认列名含"摘要"的列；若账套导出用其他列名（如"业务说明"）承载"总计/合计"，该行仍会保留并靠"空科目跳过"兜底，不会错配但会出现在结果中。
4. 极小概率路径：输入完全为空（0 数据行）时输出文件缺少"生成结果"表（make_excel 跳过空表）。实际序时账不会为空，未改。
